# Once Human Guide — working notes

## What this app is
FastAPI + SQLite game-companion API (`api_main.py`) served together with a thin
static v19 HTML shell (`once_human_guide_v19.html` + `modules/*.js`). No Node/JS
build step, no external services, no secrets.

## Non-obvious setup facts
- `api_main.py` needs `once_human.db` in the repo root. It is **gitignored** and
  is generated by `db_build.py` (prefers `database_full.json`, falls back to the
  per-table `*.json` modules). `start.sh` refuses to run without it.
- `GET /` is the API index (JSON); the human entry point is `GET /ui` (the v19
  shell). `/ohg_data.js`, `/ohg_sw.js` and `/modules/*` are served by the API as
  well, so the shell must be opened through the API, not from the file system.
- `GET /stats` needs the SQLite file (use it to check DB readiness); `/health`
  returns 200 even when the DB is missing.
- `GET /version` reports the version string stored *inside the pack*
  (`database_full.json`), currently `2026-09-30-v5-complete`, while `/stats`
  reports `version.json`'s `data_version`. Both are expected, they are different
  sources.
- Module-to-shell contract: the shell renders the workspace into `#ws` and
  writes plain hashes (`#db`, `#db/<id>`). `modules/ohg_quality.js` mounts its
  audit card into `#ws` on the `home`/`db`/`settings` routes and re-mounts after
  every `render()` (the shell rewrites `#ws` on each render). `modules/ohg_links.js`
  listens for clicks on `[data-table][data-id]` — `itemRow()` in `ohg_runtime.js`
  emits those attributes — and appends `/links` results to `#ctx .body`, or to
  `#sheet` on phone, where entities open instead.
- `.app.phone` needs `grid-template-columns:minmax(0,1fr)` and a wrapping topbar;
  without them the auto-sized implicit grid column takes the topbar's min-content
  width and the phone layout scrolls ~235 px sideways.
- `modules/ohg_selfheal.js` loads last and works silently in the background: it
  upgrades the pack when `version.json`'s `data_version` differs from the loaded
  one (re-loads `ohg_data.js?v=<target>`, then rebinds `DATA`/`META`), retries a
  failed GET once, redraws after a runtime error, reloads once when `#ws` is
  empty, re-fetches a module script that failed to load, and resets a corrupt
  `ohg_user`. Its trail is `window.OHG_selfheal` and localStorage `ohg_repairs`.
- Known mismatch: `version.json` declares `data_version 2026-10-09-v19.2-372`
  while the generated `ohg_data.js` still carries `OHG_META.version
  2026-09-30-v18-372`. So the pack channel queues a diff on every load and the
  self-heal upgrade runs but finds nothing newer to apply; regenerating
  `ohg_data.js` (via `db_build.py`) closes the gap.

## Module wrappers (easy to get wrong)
`modules/ohg_builds.js` and `modules/ohg_pack_channel.js` extend a view defined in
`ohg_runtime.js` by aliasing it and adding markup. The wrapper MUST be a function
*expression* assigned to the view name (`viewBuilds = function () {…}`). Written as
a function declaration it is hoisted, so the alias taken above it points at the
wrapper itself and the view recurses until `RangeError: Maximum call stack size
exceeded`; the shell then leaves the previous screen on display (Build Planner and
AI Agent both looked "empty" this way).

`/ui`, `/version.json`, `/ohg_data.js`, `/ohg_sw.js` and `/modules/*` are sent with
`Cache-Control: no-cache` (middleware in `api_main.py`). Without it the browser
caches these assets heuristically and keeps executing an outdated module after an
edit or a release. The service worker (`ohg_sw.js`) additionally caches modules
cache-first under `CACHE`, so bump `CACHE` (and `version.json`'s `sw_cache`) when a
module changes.

## CI (`.github/workflows/python-app.yml`)
Runs on pushes/PRs to `main`; both steps fail the job:
- `flake8 . --count --select=E9,F63,F7,F82` → must report **0** errors. This is
  fatal-error lint, so an undefined name here is a real `NameError` at runtime
  (`install_gui.py` had two: a missing `import webbrowser` and an exception
  variable captured by a deferred `lambda`).
- `pytest` → must collect at least one test, otherwise pytest exits 5 and the
  job fails. `pytest.ini` sets `pythonpath = .` so `import api_main` resolves
  from the repo root.

Run locally:
```bash
python -m pip install -r requirements.txt flake8 pytest
flake8 . --count --select=E9,F63,F7,F82 --show-source --statistics
pytest
```

## Sandbox / preview (`docker-compose.base44.yml`)
- `db` (one-shot) builds the SQLite DB; `api` runs from the bind-mounted source
  with `uvicorn --reload`; `web` (nginx, host port **3000**) is the public entry
  point. `nginx.base44.conf` forwards `/` to `/ui` so the preview lands on the
  guide UI, and passes every other path straight through to the API.
- `WATCHFILES_FORCE_POLLING=true` makes reload work across the bind mount.
- Verify: `curl http://localhost:3000/` (HTML shell), `curl http://localhost:3000/stats`,
  `curl http://localhost:3000/audit`.
